# DESIGN.md reference library

Use the bundled collection at `references/design-md/` as inspiration and a source of concrete design-system examples. It contains community-curated `DESIGN.md` files for real products and websites, not a design generator or a ready-made theme for every project.

## Workflow

1. Identify the product's audience, purpose, brand constraints, content, and target stack.
2. Search `references/design-md/` for two or three relevant examples by filename and content. Choose based on relevant patterns, not popularity alone.
3. Extract reusable design principles: palette roles, typography hierarchy, spacing, layout, surfaces, interaction, and accessibility.
4. Synthesize an original system for the user's project. Do not present the reference site's colors, logo, wording, or distinctive assets as the user's brand; preserve license and attribution requirements.
5. Produce or update the project's own `DESIGN.md` only when useful, recording tokens and actionable component/layout rules. Validate contrast, responsive behavior, and consistency in the actual interface.

The bundled files are a snapshot from the source repository and may become stale. Verify important claims against the current product/site when timeliness matters. Collection source: VoltAgent/awesome-design-md; see `references/LICENSE`.
